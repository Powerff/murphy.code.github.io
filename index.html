How to choose

只出方案 vs 会改代码

只出方案
codebase-agent-kit 全套 · eng 分析类（style / review / debt / hooks / api-layer）。 示例：@codebase-migration-plan 输出 JDK 升级蓝图，不改文件。
会改代码
eng 工作流：backend-bug-fix · backend-implement-verify* · backend-stack-upgrade · *-project-refactor。 示例：方案确认后 @backend-stack-upgrade JDK 17→21 并跑构建验证。
会提交
backend-implement-verify-commit · backend-code-commit。 其余工作流默认把变更留在工作区，由你决定是否入库。

推荐组合：kit 定全局方案 → eng 工作流落地验证 → eng 分析类做单文件质量收尾。 详细表见 eng-code-skills README 与 kit README。

03 // STANCE

Engineering stance

原则先于提示词。

  1. AI 加速，人负责上线。 产出在评审与测试前只是建议。
  2. 重构 ≠ 搬运代码。 成本在恢复调用链、状态机与隐含规则。
  3. 流程优于一次性神 Prompt。 分阶段、可回滚、有成本上限。
  4. 领域失败模式不同。 后端一致性 / 前端状态与副作用需要不同清单。
  5. 证据优于感觉。 日志、diff、构建与可复现路径优先。
